# Tierlog — 英語圏SaaSアフィリエイト自動サイト

主要AIツールの料金ページを毎日巡回 → 価格改定を検出 → 履歴として蓄積 → 静的サイトを生成 →
GitHub Pages へ自動デプロイ。**サーバー代・API利用料ゼロ**で動き続けます。

[24.rakutenn](../24.rakutenn/) の英語版ですが、**扱う商材も自動化する対象も別物**です。
その理由から書きます。

---

## 1. なぜ「物販」ではなく「SaaSの価格追跡」なのか

### 1-1. 単価が5倍違う

| | ecommerce（物販） | SaaS / AIツール |
|---|---|---|
| 平均EPC | $0.65 | **$1.20〜3.50** |
| 報酬形態 | 都度・1〜4%（eBay） | **20〜50%の継続報酬** |
| Cookie | eBayは24時間 | 30〜90日が主流 |

物販は「フロー」、SaaSは「ストック」です。$99/月のツールに20%継続なら、
1件で月$19.8が解約されるまで積み上がります。

### 1-2. Amazonは2026年に自動化の入口が閉じた

- PA-API は**新規受付を停止**し、2026年5月15日で廃止
- 後継の **Creators API は「直近30日で成約10件」が利用条件**

成約を出すためにAPIが要るのに、APIを使うには成約が要る。ゼロからの自動化の起点にできません。

### 1-3. そして「記事の自動量産」は2026年に効かなくなった

2026年3月のコアアップデートで**アフィリサイトの71%が下落**しました。名指しで叩かれたのが

- AI生成の商品比較
- メーカー仕様のコピペ
- 一次情報のないレビュー

で **-40〜70%**。24.rakutenn の型をそのまま英語に移植すると、これに正面から当たります。

一方、**編集された50〜100本規模のサイトは +30〜80%** と伸びました。
**差はAIを使ったかどうかではなく、独自データを持っているかどうかでした。**

### 1-4. だから自動化する対象を変えた

| | 旧（24.rakutenn） | 新（このプロジェクト） |
|---|---|---|
| 自動化するもの | 記事の**量産** | 少数ページの**鮮度維持** |
| ページ数 | 18記事 → 増やす | 15ツール + 9比較 = 約28ページで**固定** |
| 独自性 | 楽天APIの再表示 | **価格履歴**（誰も持っていない） |
| 時間が経つと | 記事が陳腐化する | **履歴が厚くなる = 堀が深くなる** |

「Cursorはいつ値上げしたか」に答えられるサイトは後発が絶対に追いつけません。
去年の値上げは、去年から記録していないと永久に手に入らないからです。
AI Overviews や ChatGPT に引用されるのも、この種の「日付の付いた事実」です。

> **注意**: これは集客を自動化する道具ではありません。SEOで検索流入が付くまで英語圏では
> 6ヶ月以上かかります。このシステムが保証するのは「毎日更新される独自データが
> 手間ゼロで積み上がること」だけです。

## 2. システム構成

```
main.py                  パイプライン入口
├── src/catalog.py       config の読み込みと検証（壊れた設定は起動時に落とす）
├── src/fetch.py         robots.txt遵守・レート制限つきHTTPクライアント
├── src/extract.py       ★価格抽出。signature(堅い) と plans(best-effort) の2段構え
├── src/track.py         ★履歴の蓄積と差分検出。このサイトの資産の本体
├── src/collect.py       巡回のオーケストレーション
├── src/pages.py         履歴 → ページデータ（英語の見出し文の生成もここ）
├── src/render.py        Jinja2 で docs/ に書き出し
├── src/demo.py          通信せずに「半年後の姿」を合成して確認する
├── config/site.yaml     ★運用で触る: 比較ページの組み合わせ・しきい値
├── config/tools.yaml    ★運用で触る: 追跡対象と成果リンク
├── data/prices.jsonl    ★価格履歴。絶対に消さないこと
├── data/latest.json     最終チェック結果（「いつ確認したか」の記録）
└── docs/                生成物。Pages が配信する
```

### 生成されるページ

| ページ | 役割 |
|---|---|
| `/` | **最近の価格変更フィード**。サイトの顔 |
| `/tools/<slug>/` | 現在価格 + 価格履歴テーブル + 成果リンク |
| `/compare/<a>-vs-<b>/` | 2ツールの価格を**同じ日付で**比較 |
| `/changes/` | 全変更ログ |
| `/methodology/` | 収集方法の公開。**E-E-A-Tの中核なので消さないこと** |
| `/disclosure/` | FTC開示・プライバシー |
| `/feed.xml` | **価格変更RSS**。検索に依存しない直接流入の経路 |

比較ページは `config/site.yaml` に書いた組み合わせだけを生成します。
全組み合わせの自動生成は scaled content abuse に該当するので、**やらないこと**。

## 3. セットアップ

APIキーの取得は不要です。公開されている料金ページを読むだけなので、秘密にすべき値がありません。

```powershell
pip install -r requirements.txt

# 通信せず見た目だけ確認（合成データ。赤いDEMOバーが出ます）
python main.py --demo
python -m http.server -d docs 8000     # → http://localhost:8000

# 実際に巡回して生成（履歴には書き込まない）
python main.py

# 生成物を検査（CIがデプロイ前に必ず実行する）
python main.py --verify

# 回帰テスト（CIが巡回前に必ず実行する）
pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check src/ main.py tests/
```

### テストは「過去に公開してしまった嘘」の一覧です

[tests/](tests/) の37件は思いつきで書いたものではなく、**実際に誤った価格を
公開してしまった事故から1件ずつ起こしたもの**です。

| テスト | 実際に起きたこと |
|---|---|
| `test_billed_annually_is_not_a_yearly_unit` | `$79/月・年払い` を年額として掲載（12倍のずれ） |
| `test_price_right_after_a_savings_figure_is_still_found` | 割引額の直後にある本当の価格を取り逃がし、beehiiv の2プランが空欄に |
| `test_free_named_plan_never_gets_a_paid_price` | 無料プランに隣のカードの `$10` が入った |
| `test_free_plan_absent_from_page_is_not_invented` | 無料プランが無い製品に「Free — $0」を捏造 |
| `test_plan_name_matches_on_word_boundary` | `Pro` が `products` にヒットして無関係な数字を掲載 |
| `test_new_plan_does_not_claim_the_vendor_added_it` | 抽出が改善しただけなのに「ベンダーがプランを追加した」と公開 |

**落ちたときにテストの方を緩めないこと。** 同じ嘘をもう一度公開することになります。
CI は巡回より前にこれを実行し、失敗したらその日は更新しません。
間違った価格を配るくらいなら、更新しない方がましだからです。

### ⚠️ 価格履歴を書けるのは CI だけです

手元で `python main.py` を実行しても **`data/prices.jsonl` には書き込まれません**。
書き込むのは `--record` を付けたときだけで、それを付けるのは
[daily.yml](.github/workflows/daily.yml) の1箇所に限定してあります。

**理由**: 多くのSaaSはアクセス元の国で言語と通貨を変えます。日本から Notion の
料金ページを読むと `Free` しか取れませんが、CI（米国）からは `Plus $10 / Business $20` が
正しく取れます。この2つを同じ履歴に混ぜると、

```
Notion added Plus at $10/mo        ← 嘘。日本からは読めなかっただけ
monday.com removed the Free plan   ← 嘘。同上
```

という**実際には起きていない変更**が公開されます。公開初日に実際これが6件出ました。
履歴は必ず**同じ観測地点**から取られなければならないので、手元の実行は
「巡回して生成物を確認する」までに留めてあります。

### `--verify` が守っているもの

テンプレートを触ったときに**見た目では気づかない壊れ方**だけを機械的に押さえます。

| 検査 | 見逃すとどうなるか |
|---|---|
| FTC開示バーが全ページにあるか | テンプレート1行の削除で全28ページから同時に消える。**米国法上の違反** |
| DEMOデータの混入 | 架空の価格を実価格として公開してしまう |
| canonical が本番URLか | ローカル用URLのまま公開すると全ページが他所を正規URLに指す |
| 内部リンク切れ | ツールを外したときに比較ページから参照が残る |
| 外部リンクの `rel` | 成果リンクに `sponsored` が無い＝未開示の広告 |
| sitemap / feed / robots | 壊れたXMLを送信するとGSCで登録できない |

[.github/workflows/daily.yml](.github/workflows/daily.yml) が**生成の直後・アップロードの前**に実行するので、
検査に落ちたビルドが Pages に出ることはありません。`setup.ps1` も push 前に同じ検査をかけます。

公開まで一気にやる場合（`gh auth login` だけ先に済ませておく）:

```powershell
.\setup.ps1 -RepoName tierlog
```

公開URLは `https://harypary.github.io/tierlog/` になります。

[setup.ps1](setup.ps1) が以下をまとめて実行します。

1. `config/tools.yaml` の検証
2. 初回巡回（各社の料金ページを1回ずつ読む）
3. `git init` → commit → リポジトリ作成 → push
4. **Actions に書き込み権限を付与**（後述。ここが最重要）
5. `SITE_BASE_URL` を Variable に登録
6. Pages を「GitHub Actions」ソースで有効化
7. 初回デプロイ

### ⚠️ Actions の書き込み権限について

価格履歴は**リポジトリに書き戻されることで初めて蓄積されます**。
Settings → Actions → General → Workflow permissions が **Read and write** でないと、
`daily.yml` の `contents: write` は昇格できず、**毎日「初回観測」からやり直しになり、
変更ログが永久に空のまま**になります。`setup.ps1` が自動設定しますが、失敗したら手動で。

同じ理由で、`.gitignore` に `data/` を足さないでください。

## 4. 収益化（ここだけ手作業・順番が決まっている）

**サイトが先、アフィリエイト申請が後です。** SaaS系ASPは軒並み「コンテンツサイトか
既存オーディエンス」を承認要件にしているので、この順番でしか進められません。
物販ASPと違い、承認待ちの間もサイトは通常リンクで成立します。

1. **サイトを公開する**（3章）。最低2週間ほど履歴を溜めると審査に通りやすい
2. **申請する**
   - [PartnerStack](https://partnerstack.com/) — B2B SaaS特化。800社以上。プラットフォーム承認 → 各社承認の2段階
   - [Impact](https://impact.com/) — 大手が多い
   - 各社の直接プログラム（Notion, ClickUp, ElevenLabs, beehiiv, Kit など）
3. **承認されたら `config/tools.yaml` の `affiliate` を埋める**

```yaml
  - slug: notion
    affiliate:
      program: direct
      url: "https://affiliate.notion.so/xxxxx"   # ← 発行されたリンク
      terms: "50% of first-year revenue"          # ← 承認画面の記載を書き写す
```

`url` を埋めた時点で、そのツールのリンクが `rel="nofollow sponsored"` に変わり、
「affiliate link」ラベルとFTC開示文が自動で付きます。**推測で `terms` を書かないこと**
（読者に見せる文言になります）。

`url` が1本も無い状態で `python main.py` を実行すると警告が出ます。
「動いているのに1円も入らない」状態に気づかないのが一番損なので、毎回出るようにしてあります。

### 集客担当と収益担当を混ぜている理由

Claude / Cursor / GitHub Copilot にはアフィリエイトプログラムがありません。それでも
追跡しているのは、`"how much does cursor cost"` のような検索が桁違いに多く、
**集客の入口**になるからです。そこから内部リンクで成果リンクのあるツールへ送ります。
全ページを成果リンクで埋めると「アフィリ目的のみ」と判定されます。

## 5. 抽出精度の現実（必ず読むこと）

**料金ページはAPIではなく販促物です。** 完璧なパースは不可能で、このコードは
最初からそれを前提に書いてあります。

### 2段構え

| | 何をするか | 信頼度 |
|---|---|---|
| **signature** | ページ上の価格の**集合**をハッシュ化 | **高い**。ページを作り替えられても「何かが変わった」は検出できる |
| **plans** | プラン名の近傍から金額を拾う | best-effort。外すことがある |

両者が食い違う（変わったのにどのプランか言えない）ときは `Page changed` とだけ記録し、
それ以上は主張しません。

### 掲載の判断基準

値を掲載するのは、根拠が強い順に次のいずれかを満たしたときだけです。

1. `tools.yaml` の `patterns` で明示的に指定された取り出し方（推測ゼロ）
2. プラン名から**60文字以内**にあり、かつ **`/mo` のような課金周期の表記を伴う**こと
3. `$0` であるか、プラン名自体が `Free` を含み、**かつそのプランがページに実在する**こと

この3つのどれにも当てはまらない数字は**捨てて空欄にします**。もっともらしい嘘の価格を
出すのは、価格サイトにとって唯一やってはいけないことだからです。実測では、この基準を
緩めた分だけ「隣のカードの価格」「機能表の数量」「年間割引額」が混入しました。

さらに次の3つを個別に弾いています。いずれも実際に誤った価格を公開してしまった事例です。

| 罠 | 何が起きたか |
|---|---|
| `Save $240/year` | 割引額を価格として掲載。判定前に除去する |
| `$79 per month, billed annually` | 年払いの**約束**を年額の**単位**と誤解し、12倍ずれた価格を掲載 |
| 設定にあるがページに無い `Free` | 無料プランが存在しない製品に「Free — $0」を捏造 |

### 現状（2026年8月時点の実測）

`python main.py --check` で全ツールの抽出状況を点検できます。履歴は汚しません。

```powershell
python main.py --check
```

- **完全に取れる**: cursor, github-copilot, clickup, writesonic, surfer-seo, elevenlabs, descript, framer, kit, claude
- **一部だけ**: notion, monday, copy-ai, jasper, beehiiv（無料プランのみ等。空欄表示になる）
- **外してある**: chatgpt, gemini, perplexity, grammarly, canva, midjourney, semrush, webflow
  （理由は [config/tools.yaml](config/tools.yaml) のコメントに個別に記載）

### 劣化の検出は自動化されています

料金ページの作り替えは必ず起きますが、その壊れ方は**サイト上では「価格が空欄」になるだけで
エラーが出ません**。放置すると静かに劣化します。

[check.yml](.github/workflows/check.yml) が**毎月1日**に全ツールを点検し、
`data/check.json`（前回の状態）と比較して、**悪くなったものがあるときだけ Issue を立てます**。

- 状態が下がった（`OK → PARTIAL` など）
- 取得できるプラン数が減った

ずっと `PARTIAL` のままのツールは通知しません。毎月Issueが立つと読まれなくなり、
本当に壊れた月に気づけなくなるためです。**問題が無い月は何も届きません。**

点検はCI（米国）で走ります。手元（日本）から `--check` しても構いませんが、
地域差で結果が変わるので、判断は Issue の内容を基準にしてください。
なお `--save-check`（比較基準の更新）はCI専用です。

### 精度を上げる方法 = このサイトの主なメンテ作業

近傍探索が外れるツールは `patterns` で上書きします。Cursor が実例です。

```yaml
    patterns:
      Hobby:  'name: Hobby\s*\n\s*price: \$?([\d.]+)'
      Pro:    'name: Pro\s*\n\s*price: \$?([\d.]+)'
```

金額を捉えるグループを**1つだけ**書きます（起動時に検証され、違えば例外で止まります）。
`--check` で `PARTIAL` や `NG` が出たツールに patterns を足していくのが、
**このサイトを育てる作業そのもの**です。外してあるツール（特に検索需要が最大の chatgpt）を
戻せれば、それだけ集客力が上がります。

### 既知の限界

- **JavaScriptを実行しない**ので、SPA型の料金ページは読めません
- **地域価格**: 日本から実行するとGoogleなど一部サイトが円建て・日本語を返します。
  `$` 以外の通貨は抽出対象外なので誤った値は出ませんが、CI（米国リージョン）と
  手元で結果が変わることがあります
- **月額/年額の切り替え**: 既定表示が年額のページは年額を記録します（表に明示されます）。
  A/Bテストで既定が揺れるサイトは、履歴に往復のノイズが出ます

## 6. 公開後の運用ループ

自動化されるのはデータ収集までです。ここだけは手を動かす価値があります。

1. **Google Search Console に登録し `sitemap.xml` を送信**
   - プロパティは「**URLプレフィックス**」で `https://<user>.github.io/<repo>/`
   - 所有権確認は「HTMLファイル」方式。ダウンロードしたファイルを `site_root/` に置けば、
     毎日の再生成後も維持されます
   - サイトマップ欄には**先頭スラッシュなしで `sitemap.xml`**

   > ⚠️ プロジェクトページ（サブディレクトリ公開）だと、クローラは robots.txt を
   > **ホストのルートしか読みません**。`/<repo>/robots.txt` の `Sitemap:` 行は無視されるので、
   > **GSCでの手動送信が唯一の登録経路**です。

2. **1〜2ヶ月後、検索パフォーマンスを見る**
   → 表示回数が付いたツール名・比較の組み合わせが分かる

3. **反応があった組み合わせを `config/site.yaml` の `comparisons` に足す**
   → 反応の無いものは削る。**闇雲に増やさない**こと（scaled content abuse）

4. **`--check` が壊れを報告したら `patterns` を書く**

このループを回すのがこのシステムの本来の使い方です。

## 7. 守るべきルール

コード側で対応済みで、**主要なものは `python main.py --verify` が自動検出します**（3章）。
それでもテンプレートを編集するときは意図を理解した上で触ってください。

### 法令・規約

- **FTC開示（16 CFR Part 255）** — 全ページ最上部の開示バー
  （[templates/base.html](templates/base.html) の `.disclosure-bar`）と、成果リンク横の
  `affiliate link` ラベル。**どちらも削除すると米国法上の違反になります**
- **リンク属性** — 成果リンクは `rel="nofollow sponsored noopener"`。
  ただし `affiliate.url` が空のときは `sponsored` を付けません（広告でないものを
  広告と申告しないため）
- **商標** — 公開URLに追跡対象ベンダーの商標を含めないこと。`setup.ps1` の
  `-RepoName` で独立したトラッカーだと分かる名前にする

### クローラとしての行儀

毎日他社のサーバを叩き続ける以上、ここを守れないとIPごとブロックされてサイトが死にます。

- **robots.txt を必ず確認** — Disallow なら取得しない。ステータスの扱いは
  RFC 9309 に厳密に従う（直感と逆なので注意）:
  **4xx（401/403を含む）は「制限なし」**（§2.3.1.3）、
  **5xxと通信不能は「全面禁止」**（§2.3.1.4）。
  403を禁止と誤解すると、実際には巡回してよいサイトを取りこぼす
- **Crawl-delay を尊重** — 相手が明示していればこちらの設定値より優先
- **同一ホストへ最低2秒間隔**（`config/site.yaml` の `request_interval_sec`）。
  1秒未満には設定できないようにしてあります
- **User-Agent で名乗る** — 連絡先URLを含める。苦情の窓口が無いクローラは問答無用で弾かれます
- **429 の `Retry-After` に従う**

### データの誠実さ

- **推測で価格を埋めない** — 取れなかったものは空欄
- **古い価格を現在価格として出さない** — 14日確認できなければ価格を伏せる
  （`stale_after_days`）。履歴は古くならないのでそのまま残す
- **`--demo` の出力を公開しない** — 合成データなので赤いDEMOバーが出ます
- **成果リンクの有無で扱いを変えない** — 収集スクリプトはどのツールが報酬を払うかを
  知りません。これは人格の話ではなくコードの構造の話で、
  だから [methodology](templates/methodology.html) で方法を公開しています
